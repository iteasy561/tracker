# ระบบติดตามงาน (Task Tracking System)

ระบบติดตามงานแบบไฟล์เดียว เขียนด้วย Flask + SQLite ส่วนหน้าใช้ Tailwind CSS (CDN)
แนวคิดหลักของระบบคือ **งาน → ขั้นตอนการดำเนินงาน → เอกสาร/หนังสือที่แนบในแต่ละขั้นตอน**

> เอกสารทุกฉบับผูกกับงานและขั้นตอนที่มันเกิดขึ้นเสมอ ไม่ได้เป็นทะเบียนหนังสือแยกต่างหาก
> และในแต่ละขั้นตอน **แนบไฟล์ได้หลายไฟล์ต่อครั้ง และแนบเพิ่มได้ไม่จำกัดจำนวนครั้ง**

---

## ความสามารถ

### งาน (Task)
- สร้าง / แก้ไข / ลบงาน พร้อมชื่องาน รายละเอียด ประเภทงาน ผู้มอบหมาย ผู้รับผิดชอบ
- ระดับความสำคัญ 4 ระดับ: ต่ำ · ปกติ · สูง · ด่วนที่สุด
- สถานะ 5 สถานะ: รอดำเนินการ · กำลังดำเนินการ · รอตรวจสอบ · เสร็จสิ้น · ยกเลิก
- **กำหนดส่ง (due date)** พร้อมนับวันคงเหลือ และเน้นสีแถวที่เกินกำหนดอัตโนมัติ
- ค้นหา/กรองตามคำค้น สถานะ ความสำคัญ ผู้รับผิดชอบ และมุมมอง "เฉพาะที่ยังไม่ปิด / เฉพาะเกินกำหนด"

### ขั้นตอนการดำเนินงาน (Step)
- แบ่งงานออกเป็นขั้นตอน แต่ละขั้นตอนมีผู้รับผิดชอบ กำหนดส่ง สถานะ และหมายเหตุของตัวเอง
- กำหนดขั้นตอนเริ่มต้นได้ตั้งแต่ตอนสร้างงาน (พิมพ์บรรทัดละ 1 ขั้นตอน)
- ปุ่มลัด "เริ่ม / เสร็จ" เลื่อนลำดับ ↑ ↓ แก้ไขรายละเอียด และลบขั้นตอน
- **% ความคืบหน้าของงานคำนวณอัตโนมัติ** จากสัดส่วนขั้นตอนที่เสร็จ
  - มีขั้นตอนเสร็จบางส่วน และงานยัง "รอดำเนินการ" → เปลี่ยนเป็น "กำลังดำเนินการ" ให้
  - ขั้นตอนเสร็จครบ 100% → เปลี่ยนสถานะงานเป็น "รอตรวจสอบ"
- ลบขั้นตอนแล้วเอกสารที่เคยแนบไว้ไม่หาย จะย้ายไปอยู่ระดับงานแทน

### เอกสาร / หนังสือแนบ (File)
- ประเภทเอกสาร: **หนังสือเข้า · หนังสือออก · เอกสารประกอบ**
- เก็บเลขที่หนังสือ ลงวันที่ เรื่อง หน่วยงานจาก/ถึง หมายเหตุ ผู้แนบ
- อัปโหลดได้หลายไฟล์พร้อมกัน และแนบซ้ำในขั้นตอนเดิมได้ตลอดเวลา
- แนบไฟล์ไปพร้อมกับ "รายงานความคืบหน้า" ได้
- บันทึกข้อมูลหนังสือไว้ก่อนโดยยังไม่แนบไฟล์จริงก็ได้ (เช่น ลงเลขที่หนังสือรอไฟล์สแกน)
- หน้าค้นหาเอกสารข้ามงานทั้งระบบ พร้อมแสดงบริบท "งาน › ขั้นตอน" ของทุกฉบับ

### รายงานความคืบหน้า (Update)
- บันทึกรายงานได้ทั้งระดับงานและระบุว่าเป็นของขั้นตอนไหน
- ปรับ % และสถานะงานไปพร้อมกัน แนบไฟล์ประกอบรายงานได้
- แสดงเป็นไทม์ไลน์เรียงจากล่าสุด

### สรุปรายงาน
- KPI: งานทั้งหมด · เสร็จสิ้น · อัตราความสำเร็จ · ขั้นตอนเกินกำหนด · เอกสารแนบ
- กราฟแท่ง: งานตามสถานะ · ขั้นตอนทั้งระบบ · เอกสารตามประเภท
- ตาราง: สรุปตามผู้รับผิดชอบ (งาน/เสร็จ/เกินกำหนด/ความคืบหน้าเฉลี่ย), ตามประเภทงาน,
  ขั้นตอนที่เกินกำหนด, เอกสารแนบรายเดือน, งานเกินกำหนด
- กรองตามช่วงวันที่สร้างงาน
- **ส่งออก CSV 3 ชุด**: งาน · ขั้นตอน · เอกสาร (ใส่ BOM มาให้ เปิดใน Excel ภาษาไทยไม่เพี้ยน)

### อื่น ๆ
- แสดงวันที่เป็นพุทธศักราชแบบไทย เช่น `26 ก.ย. 69`
- ฟอนต์ Sarabun รองรับภาษาไทยเต็มรูปแบบ
- รองรับจอมือถือ (ทดสอบที่ความกว้าง 375px ไม่มีการเลื่อนแนวนอน)
- มีข้อมูลตัวอย่างให้อัตโนมัติเมื่อสร้างฐานข้อมูลครั้งแรก (6 งาน · 23 ขั้นตอน · 10 เอกสาร)

## การติดตั้งและใช้งาน

ต้องมี Python 3.8 ขึ้นไป

```bash
pip install flask
```

```bash
python app.py
```

เปิดเบราว์เซอร์ที่ **http://127.0.0.1:5000**

โหมดพัฒนา (auto-reload เมื่อแก้ไฟล์ และแสดง traceback):

```bash
python app.py --debug
```

> การรันครั้งแรกจะสร้าง `tracker.db` พร้อมข้อมูลตัวอย่างให้เอง
> ถ้าต้องการเริ่มจากฐานข้อมูลว่าง ให้ลบ `tracker.db` แล้วลบฟังก์ชัน `seed_demo()`
> ที่ถูกเรียกใน `init_db()` ออก (หรือแค่ลบข้อมูลตัวอย่างในหน้าเว็บ)

## โครงสร้างไฟล์

```
ep2/
├── app.py         # ทั้งระบบอยู่ในไฟล์นี้ไฟล์เดียว (โค้ด + เทมเพลต + สไตล์)
├── tracker.db     # ฐานข้อมูล SQLite (สร้างอัตโนมัติตอนรันครั้งแรก)
├── uploads/       # ไฟล์แนบที่อัปโหลด (ตั้งชื่อใหม่เป็น UUID)
└── README.md
```

เทมเพลตทั้งหมดเก็บเป็นสตริงใน `app.py` แล้วโหลดผ่าน `jinja2.DictLoader`
จึงยังใช้ `{% extends %}` / `{% macro %}` ได้ตามปกติโดยไม่ต้องมีโฟลเดอร์ `templates/`

| เทมเพลต | หน้าที่ |
|---|---|
| `base.html` | เลย์เอาต์หลัก เมนู ตั้งค่า Tailwind แจ้งเตือน flash |
| `macros.html` | badge สถานะ/ความสำคัญ/ประเภทเอกสาร, แถบความคืบหน้า, กราฟแท่ง, KPI, ฟอร์มแนบไฟล์ |
| `dashboard.html` · `tasks.html` · `task_form.html` · `task_detail.html` · `files.html` · `reports.html` | หน้าต่าง ๆ ของระบบ |

## โครงสร้างฐานข้อมูล

```
tasks ──┬── steps ──┐
        ├── updates ┤
        └── files ──┘   (files ผูกกับ task เสมอ, ผูกกับ step/update ได้ด้วย)
```

| ตาราง | ฟิลด์สำคัญ |
|---|---|
| `tasks` | `title`, `description`, `category`, `owner`, `assignee`, `priority`, `status`, `progress`, `start_date`, `due_date`, `done_date` |
| `steps` | `task_id`, `seq`, `name`, `owner`, `due_date`, `status`, `done_date`, `note` |
| `updates` | `task_id`, `step_id`, `note`, `progress`, `status`, `reporter` |
| `files` | `task_id`, `step_id`, `update_id`, `kind`, `doc_no`, `doc_date`, `subject`, `counterparty`, `note`, `uploader`, `filename`, `stored_name`, `filesize` |

- `files.stored_name` คือชื่อไฟล์จริงบนดิสก์ (UUID) ส่วน `filename` คือชื่อเดิมที่ผู้ใช้เห็นและใช้ตอนดาวน์โหลด
- ลบงาน → ลบขั้นตอน รายงาน เอกสาร และไฟล์บนดิสก์ทั้งหมดของงานนั้น
- ลบขั้นตอน → เอกสารและรายงานยังอยู่ แต่ `step_id` ถูกตั้งเป็น `NULL`

## เส้นทาง (Routes)

| Method | Path | คำอธิบาย |
|---|---|---|
| GET | `/` | ภาพรวม |
| GET | `/tasks` | รายการงาน + ตัวกรอง |
| GET/POST | `/tasks/new` | สร้างงาน (พร้อมขั้นตอนเริ่มต้น) |
| GET | `/tasks/<id>` | รายละเอียดงาน ขั้นตอน เอกสาร รายงาน |
| GET/POST | `/tasks/<id>/edit` | แก้ไขงาน |
| POST | `/tasks/<id>/delete` | ลบงาน |
| POST | `/tasks/<id>/report` | บันทึกรายงานความคืบหน้า (แนบไฟล์ได้) |
| POST | `/tasks/<id>/steps` | เพิ่มขั้นตอน |
| POST | `/tasks/<id>/upload` | แนบเอกสาร (ระบุ `step_id` เพื่อผูกกับขั้นตอน) |
| POST | `/steps/<id>/update` | แก้ไขรายละเอียดขั้นตอน |
| POST | `/steps/<id>/status/<status>` | เปลี่ยนสถานะขั้นตอนแบบเร็ว |
| POST | `/steps/<id>/move/<up\|down>` | เลื่อนลำดับขั้นตอน |
| POST | `/steps/<id>/delete` | ลบขั้นตอน |
| GET | `/files` | ค้นหาเอกสารทั้งระบบ |
| GET | `/files/<id>/download` | ดาวน์โหลดไฟล์แนบ |
| POST | `/files/<id>/delete` | ลบเอกสารแนบ |
| GET | `/reports` | สรุปรายงาน |
| GET | `/reports/export/<tasks\|steps\|files>.csv` | ส่งออก CSV |

## การปรับแต่ง

แก้ค่าคงที่ด้านบนของ `app.py` ได้เลย

```python
STATUSES      = ["รอดำเนินการ", "กำลังดำเนินการ", "รอตรวจสอบ", "เสร็จสิ้น", "ยกเลิก"]
PRIORITIES    = ["ต่ำ", "ปกติ", "สูง", "ด่วนที่สุด"]
STEP_STATUSES = ["รอดำเนินการ", "กำลังดำเนินการ", "เสร็จสิ้น"]
CATEGORIES    = ["งานบริหาร", "งานวิชาการ", "งานการเงิน", "งานพัสดุ", "งานบุคคล", "งานโครงการ", "อื่น ๆ"]
KINDS         = ["หนังสือเข้า", "หนังสือออก", "เอกสารประกอบ"]
ALLOWED_EXT   = {"pdf", "doc", "docx", "xls", "xlsx", "ppt", "pptx",
                 "png", "jpg", "jpeg", "gif", "zip", "rar", "txt", "csv"}
```

- ขนาดอัปโหลดสูงสุดต่อครั้ง: `app.config["MAX_CONTENT_LENGTH"] = 32 * 1024 * 1024` (32 MB)
- สีของระบบกำหนดไว้ใน `tailwind.config` ภายในเทมเพลต `BASE`

> หมายเหตุ: ถ้าเพิ่ม/ลบค่าใน `STATUSES` หรือ `KINDS` ควรอัปเดต mapping สีใน
> `macros.html` (`status_badge`, `kind_badge`) และในหน้า dashboard/reports ด้วย

## ข้อควรทราบก่อนใช้งานจริง

ระบบนี้เหมาะกับการใช้ภายในหน่วยงาน/ทีมเล็ก ถ้าจะนำขึ้นใช้งานจริงควรทำเพิ่ม

1. **ยังไม่มีระบบล็อกอิน** ทุกคนที่เข้าถึง URL ได้จะแก้ไขข้อมูลได้ทั้งหมด
   ควรเพิ่มการยืนยันตัวตน หรือจำกัดให้เข้าถึงได้เฉพาะเครือข่ายภายใน
2. **เปลี่ยน `SECRET_KEY`** เป็นค่าที่สุ่มขึ้นเอง (ใช้สำหรับ session/flash message)
3. `app.run()` เป็นเซิร์ฟเวอร์สำหรับพัฒนา ใช้งานจริงควรรันหลัง WSGI server เช่น
   `waitress-serve --port=8000 app:app` หรือ gunicorn + reverse proxy
4. **สำรองข้อมูล** โดยคัดลอกทั้ง `tracker.db` และโฟลเดอร์ `uploads/` คู่กันเสมอ
5. ถ้าเปิดให้เข้าจากเครื่องอื่นในวง LAN ให้แก้เป็น `app.run(host="0.0.0.0", port=5000)`

## สิ่งที่ผ่านการทดสอบแล้ว

- ทุกหน้าตอบสถานะ 200 และแสดงผลถูกต้อง
- สร้าง/แก้ไข/ลบงาน · เพิ่ม/เลื่อน/แก้ไข/ลบขั้นตอน · การคำนวณ % อัตโนมัติ
- อัปโหลดหลายไฟล์พร้อมกัน และอัปโหลดซ้ำในขั้นตอนเดิม
- บันทึกรายงานพร้อมไฟล์แนบ · ดาวน์โหลดไฟล์ (ชื่อไฟล์ภาษาไทยถูกต้อง)
- ปฏิเสธนามสกุลไฟล์ที่ไม่อนุญาต (เช่น `.exe`)
- ลบขั้นตอนแล้วเอกสารไม่สูญหาย · ลบงานแล้วไฟล์บนดิสก์ถูกลบตามครบ
- ส่งออก CSV ทั้ง 3 ชุด
- แสดงผลบนจอกว้าง 375px โดยไม่มี horizontal scroll
